# AI로 실제 서비스 배포하기: CompressDeck 재현 가이드

이 문서는 **"AI에게 코딩 시켜 실제 서비스 배포"** 과정을 다른 사람도 그대로 따라 할 수 있도록 정리한 실행 가이드입니다.  
목표는 단순 기능 구현이 아니라, **애드센스 승인 가능성 + 실사용 문제 해결형 UX**를 갖춘 사이트를 만드는 것입니다.

---

## 1) 프로젝트 목표 (복붙용)

아래 문장을 AI에게 첫 프롬프트로 전달하세요.

```text
현재 사이트 구조를 유지한 채, 실제 서비스 수준으로 개선해줘.

목표:
- 애드센스 승인 가능성 증가
- SEO/GEO 강화
- 사용자 신뢰 증가
- 체류시간 증가
- "AI 양산 사이트" 느낌 제거
- 실제 툴 서비스 느낌 강화

조건:
- 과한 애니메이션 금지
- 모바일 우선
- 기존 SEO/성능 유지
- 광고 과배치 금지(콘텐츠 우선)
```

---

## 2) AI에게 실제로 넣은 핵심 작업 프롬프트 구조

아래 순서대로 요청하면 결과가 안정적으로 나옵니다.

### Prompt A — 서비스 포지셔닝 정리

```text
현재 구조는 유지하고 전체 리디자인 없이,
"핵심 차별성 강화 + 실사용 문제 해결" 중심으로 보완해줘.

최종 느낌:
❌ 기능 많은 무료 툴 사이트
⭕ 업로드 오류 해결 특화 플랫폼
```

### Prompt B — 메인페이지 문제 해결 카피 강화

```text
Hero는 유지하고 문제 해결 문구를 자연스럽게 추가해줘:
- 사람인/잡코리아/공공기관 업로드 오류 해결
- 아이폰 HEIC 업로드 문제 해결
- PDF 제출 전 이미지 최적화
- 메일 첨부용 이미지 압축
```

### Prompt C — 문제 카드 섹션 추가

```text
메인에 "자주 해결하는 문제" 카드 섹션 추가해줘.
예시:
- 사람인 사진 용량 초과
- 잡코리아 업로드 실패
- 아이폰 HEIC 파일 안 열림
- PDF 제출 용량 초과
- 카카오톡 사진 전송 느림

각 카드는 관련 블로그/도구로 링크 연결.
```

### Prompt D — HEIC 기능 실구현

```text
HEIC -> JPG를 로드맵이 아니라 실제 동작하게 구현해줘.

조건:
- 브라우저 처리
- 서버 저장 없음
- 모바일 지원
- 여러 파일 업로드 가능
- 다운로드 버튼 제공

라이브러리: heic2any
```

### Prompt E — 추천 압축 모드 추가

```text
이미지 압축 페이지에 추천 모드 버튼 추가:
- 사람인 제출용
- 이메일 첨부용
- 카카오톡 전송용
- 웹사이트 업로드용

선택 시 품질/해상도 추천값 자동 적용.
UI는 단순 버튼형.
```

### Prompt F — 모바일 GNB 햄버거 메뉴

```text
모바일 반응형 맞춰서 GNB 햄버거 메뉴 바로 추가해줘.
데스크톱 메뉴는 유지하고 모바일에서만 토글되게 해줘.
```

## 3) 실제 작업 명령어 (터미널)

```bash
# 개발 서버
npm run dev

# HEIC 라이브러리 설치
npm install heic2any

# 배포 전 검증
npm run build
```

선택:

```bash
# 린트 점검
npm run lint
```

## 4) 애드센스 승인 가능성 높이기 위해 실제로 한 일

### A. 신뢰(Trust) 요소 강화

- "브라우저 처리", "회원가입 없음", "서버 저장 없음"을 반복적으로 명시
- 홈 하단에 신뢰/문제원인 섹션 배치
- 과장 카피보다 실제 제출 상황 중심 문구 사용

### B. 콘텐츠 우선 구조 유지

- 첫 화면 광고 도배 피함
- 광고 슬롯은 유지하되 본문/도구/가이드가 먼저 보이도록 구성

### C. SEO + GEO(질문형 탐색) 강화

- 문제 해결형 문장 추가  
  (예: "사람인 업로드 오류", "HEIC 안 열림", "PDF 용량 초과")
- FAQ/HowTo/구조화 데이터 유지·보강
- 내부링크 강화 (도구 ↔ 블로그 연결)

### D. 실사용성 강화

- HEIC -> JPG 실제 기능 제공
- 업로드 맥락 기반 추천 모드(사람인/메일/카톡/웹)
- 모바일 GNB 개선으로 접근성/탐색성 향상

### E. 품질/성능 유지

- 기존 레이아웃 대공사 없이 개선
- 과한 애니메이션 없이 가벼운 UI 유지
- 빌드 통과 확인 후 반영

---

## 5) "AI 양산 사이트"처럼 보이지 않게 하는 기준

- 기능 나열보다 **문제 해결 시나리오**를 먼저 노출
- 문구를 "무료/빠름"만 반복하지 않고, **어디서 막히는지**를 명확히 씀
- 블로그를 템플릿 반복이 아닌 실제 오류 사례 중심으로 확장
- 도구 페이지에 사용 사례/FAQ/관련 도구를 실제 업무 흐름으로 연결

## 6) 바로 사용 가능한 최종 프롬프트 (원샷)

```text
현재 사이트 구조/SEO/성능은 유지하고, 전체 리디자인 없이 실사용 문제 해결형으로 고도화해줘.

반드시 반영:
1) Hero에 업로드 오류 해결 문구 추가
2) 메인에 "자주 해결하는 문제" 카드 섹션 추가
3) HEIC->JPG 실제 구현(브라우저 처리, 다중 업로드, 다운로드)
4) 이미지 압축 추천 모드(사람인/이메일/카톡/웹) 추가
5) 블로그/도구 내부링크 강화
6) 하단에 "왜 업로드 오류가 발생하나요?" 섹션 추가
7) 모바일 햄버거 GNB 추가

제약:
- 과한 애니메이션 금지
- 모바일 우선
- 광고 과배치 금지
- build 통과 확인
```
